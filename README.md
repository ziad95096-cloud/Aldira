# فرحتي — دعوة تشبه حكايتكم

منصة عربية متجاوبة لإنشاء دعوات زفاف رقمية، معاينتها، وحفظ الحجوزات ومشاركتها برابط خاص. الواجهة تدعم العربية واتجاه RTL، والخادم يستخدم Express وقاعدة SQLite محلية.

## المتطلبات

- Node.js إصدار 22.9 أو أحدث.
- npm.

## التشغيل المحلي على Windows

1. افتح PowerShell داخل مجلد المشروع وثبّت الحزم:

   ```powershell
   npm install
   ```

2. انسخ ملف إعدادات البيئة، ثم عيّن كلمة مرور قوية وفريدة للوحة الإدارة:

   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```

   عدّل `ADMIN_PASSWORD` في `.env` إلى كلمة مرور قوية لا تستخدمها في موقع آخر. لا ترفع `.env` إلى Git.

3. شغّل الخادم والواجهة معاً:

   ```powershell
   npm run dev
   ```

4. افتح عنوان Vite الظاهر في الطرفية (غالباً `http://localhost:5173`). لوحة الإدارة على `http://localhost:5173/#/admin`.

تعمل الواجهة عادة على المنفذ 5173، وواجهة API على `http://localhost:3001`. تُنشأ قاعدة البيانات `data/farhati.sqlite` تلقائياً في أول تشغيل، وتُضاف إليها تصميمات تجريبية.

## بناء نسخة الإنتاج

```powershell
npm run build
$env:NODE_ENV = "production"
npm start
```

يخدم Express ملفات `dist` وواجهة API معاً بعد البناء. قبل النشر، اضبط `ADMIN_PASSWORD` على قيمة قوية وفعّل HTTPS لدى مستضيف التطبيق. يمكن تحديد مسار قاعدة البيانات بمتغير `DATABASE_PATH`، والمنفذ بمتغير `PORT`.

## ما يتضمنه الإصدار الأول

- صفحة رئيسية، مجموعات حسب الأسلوب، ومعرض تصميمات مع بحث وفلاتر للأسلوب واللون والسعر.
- معاينة لكل تصميم، ونموذج إنشاء دعوة يعرض معاينة مباشرة أثناء التحرير.
- أسماء العروسين والعائلتين، الموعد، المكان، رابط خريطة، الرسالة، اللون، الخط، وصورة/خلفية اختيارية عبر رابط صورة.
- رابط دعوة عشوائي وفريد، صفحة رقمية مناسبة للهاتف، عدّاد للموعد، ومشاركة عبر واتساب أو نسخ الرابط.
- إنشاء رقم حجز فريد وحفظ الطلب في SQLite بحالة «قيد المراجعة».
- لوحة إدارة محمية بكلمة المرور لمراجعة الحجوزات وتعديل بياناتها وحالاتها، وإضافة التصميمات وتعديلها وحذف غير المستخدم منها.
- حماية تسجيل الدخول من المحاولات المتكررة، وجلسات إدارة عبر Cookie من نوع `HttpOnly` و`SameSite`.

## حدود الإصدار التجريبي

- لا يتضمن الإصدار دفعاً إلكترونياً أو إرسال رسائل/دعوات تلقائياً؛ الحجز يتطلب متابعة يدوية من لوحة الإدارة.
- صور التصميمات التجريبية رسومات SVG أصلية داخل المشروع وتعمل دون اتصال. يمكن استخدام رسومات المشروع أو رابط صورة مباشر في إعدادات التصميم؛ والخطوط تستخدم Google Fonts عند توافر الإنترنت مع خطوط احتياطية محلية.
- رفع الصور إلى الخادم غير مفعّل؛ أدخلوا رابط صورة مباشر يبدأ بـ `https://`.
- قاعدة البيانات محلية، لذلك يلزم استخدام تخزين دائم وأخذ نسخ احتياطية عند النشر.
- روابط `localhost` تعمل على جهاز المطوّر فقط؛ لمشاركة الدعوات مع الآخرين، انشروا الموقع والخادم على عنوان إنترنت عام أو نطاق خاص بكم.

## استيراد القوالب الكاملة

من لوحة الإدارة اختر ZIP أو ملف HTML منفردًا أو عدة ملفات مترابطة (HTML وCSS والصور والوسائط) ثم اضغط زر التحليل المناسب للمصدر. عند رفع مجموعة ملفات حافظ على المسارات النسبية في أسماء المسارات؛ ZIP هو الخيار الأنسب للمجلدات. رفع HTML منفرد لا يرفق تلقائيًا CSS أو الصور أو الخطوط والموارد الخارجية. الاختيار والفحص لا يكتبان ملفات أو قاعدة البيانات. بعد مراجعة تقرير التحويل والمعاينة اضغط «تأكيد الاستيراد كمسودة». لا يظهر القالب للعملاء حتى تفعّله صراحة من زر التفعيل في صفه.

صيغة `manifest.json` بإصدار 1:

```json
{
  "formatVersion": 1,
  "title": "حديقة الورد",
  "style": "رومانسي",
  "color": "وردي وعاجي",
  "price": 300,
  "description": "دعوة بألوان الورود",
  "featured": true,
  "theme": { "accent": "#a86e76", "background": "#fffaf6", "fontKey": "serif" },
  "cover": "assets/cover.webp",
  "sections": [
    { "id": "hero", "type": "hero", "title": "بكل الحب", "image": "assets/cover.webp", "visible": true, "order": 0 },
    { "id": "message", "type": "message", "title": "رسالة الدعوة", "editableFields": ["message", "primary_color"], "visible": true, "order": 1 },
    { "id": "venue", "type": "venue", "editableFields": ["maps_url"], "visible": true, "order": 2 }
  ]
}
```

الأنواع المسجلة في React هي `hero`, `families`, `message`, `event`, `venue`, `gallery`, `video`, و`music`. أقسام الصوت والفيديو تستخدم عناصر تحكم واضحة بلا تشغيل تلقائي. الأقسام تعرض البيانات المعروفة من الدعوة فقط؛ لا يُنفّذ JavaScript أو HTML من ZIP. الحقول القابلة للتعديل المقبولة هي أسماء العروسين والعائلتين، الرسالة، التاريخ والوقت والمكان، رابط الخريطة، اللون، الخط، وصور الغلاف والخلفية. تقبل الحزمة `manifest.json` في جذر ZIP أو تحته مجلد رئيسي واحد، وتقبل المجلدات المتداخلة داخل `assets/`؛ كل مسار في manifest نسبي إلى جذر القالب ويبدأ بـ`assets/`. تستخدم الشرطة `/` (وتُطبّع `\\` الآمنة)، وتُقبل الأسماء العربية والمسافات. الملفات بصيغة PNG أو JPG/JPEG أو WebP للصور، أو MP3 للصوت، أو MP4/WebM للفيديو؛ ويجب أن يطابق المحتوى الفعلي الامتداد. حد طلب الرفع 12 ميجابايت، والأرشيف 12 ميجابايت، والملف بعد الفك 8 ميجابايت، والمجموع بعد الفك 32 ميجابايت، وعدد المدخلات 25. تُرفض SVG والملفات التنفيذية والروابط الرمزية والمسارات المطلقة أو التي تحاول الخروج من الجذر والوسائط غير المستخدمة.

### تحويل القوالب القديمة بصيغة HTML

يمكن رفع HTML منفرد أو مجموعة ملفات أو ZIP قديم. التحويل يقرأ HTML وCSS كبيانات نصية فقط، ولا يشغّل JavaScript أو HTML. يلتقط عنوان الصفحة والعناوين وبعض الفقرات، ولون الخلفية/الإبراز والخط الأقرب، والصور المحلية المشار إليها في `src` أو CSS `url(...)`. تُحل المراجع `../` فقط إن انتهت داخل جذر الأرشيف؛ وتظهر المراجع المفقودة أو المطلقة في تقرير الفحص. ثم ينشئ manifest داخليًا من أقسام React المسجلة ويعرض معاينة ثابتة وملاحظات ما لم ينتقل. تُحفظ الفقرة الملتقطة كنص ثابت اختياري (حتى 500 حرف) في قسم الرسالة، ويعرضها React كنص عادي مُهرَّب، إلى جانب رسالة الدعوة التي يخصصها العميل.

يقبل التحويل صفحة `index.html` في الجذر أو داخل مجلد رئيسي واحد، وملفات CSS/JS والصور والصوت والفيديو المحلية ذات الأنواع المدعومة. يقبل أيضًا `package.json` لعرض متطلبات المشروع وتبعياته دون تثبيتها أو تشغيل أوامر البناء. لا تُضمّن ملفات HTML/CSS/JS في القالب الجديد. JavaScript لا يُنفّذ ولا يُنقل؛ SVG يُرفض ويجب تصديره يدويًا إلى PNG/JPEG/WebP بعد مراجعته. ملفات الخطوط لا تُرفع؛ يختزل اختيار الخط إلى `serif` أو `sans`. الخلفيات ذات الصور المحلية يمكن نقلها إذا ظهرت في CSS `url(...)`، أما التخطيطات المعقدة والتدرجات والظلال والحركات والتفاعلات فلن تبقى كما كانت، وتظهر كتنبيهات للمراجعة اليدوية. النصوص الثانوية التي لا تلائم حقول الدعوة تظهر ضمن الملاحظات وتحتاج نقلًا يدويًا.

بعد مراجعة المعاينة والتنبيهات، أكد الاستيراد لحفظ الناتج كمسودة غير منشورة. استخدم `manifest.json` في ZIP الجديد لأي تعديلات لاحقة أو لإعادة النقل اليدوي للأجزاء التي لم تتحول. إذا لم توجد صورة غلاف محلية مرتبطة بـHTML/CSS، يرفض التحويل ويطلب ربط صورة محلية آمنة.

تُخزن أصول القوالب في `public/media/templates/` افتراضياً، ويمكن ضبط جذر تخزين دائم عبر `MEDIA_ROOT`. في التطوير تُخدم الملفات على مسار `/media/` من الخادم المحلي. تأكدوا من إعداد تخزين دائم في بيئة الاستضافة قبل النشر؛ لا يرفع التطبيق الملفات إلى خدمات خارجية.

## الدعوات وإصدارات القوالب

كل استيراد أو تعديل إداري ينشئ إصداراً ثابتاً. ترتبط كل دعوة بمعرّف إصدار ونسخة تخصيص خاصة بها، ولذلك لا يؤثر تعديل قالب أو دعوة على دعوات أخرى. إيقاف القالب يمنعه من الدعوات الجديدة ويبقي روابط الدعوات القائمة صالحة. المسار `GET /api/admin/templates/:id/versions` محمي بجلسة الإدارة.

عند إنشاء دعوة يصدر الخادم رمز تعديل عشوائياً قوياً، ويحفظ بصمته فقط. يستخدم محرر الدعوة الرمز عبر رأس `X-Invitation-Edit-Token`؛ لا تكفي معرفة رابط الدعوة لتعديلها، ولا يستطيع رمز دعوة تعديل غيرها. يحتفظ المتصفح بالرمز في `sessionStorage` لهذه الجلسة. فقدانه يعني أن تعديل العميل يتطلب مساعدة الإدارة؛ لا يوجد حساب عميل أو استعادة ذاتية للرمز. يمكن للإدارة تعديل الحجوزات عبر جلستها المحمية.

رفع الصور من جهاز العميل متاح في وضع تعديل الدعوة، ويقتصر على PNG/JPEG/WebP وبحد 8 ميجابايت، مع فحص المحتوى الفعلي وتخزين كل ملف داخل مسار الدعوة. إنشاء الدعوة وتخصيصها الأولي ما زال يستخدم حقول الباني الحالي؛ للوصول إلى رفع صورة محلية، احفظوا الدعوة أولاً ثم افتحوا «تعديل الدعوة لاحقاً» في جلسة المتصفح نفسها.

## الترحيلات والنسخ الاحتياطية والاختبارات

يُنشأ مخطط الإصدارات ورمز التعديل وحالة تفعيل القالب بترحيلات SQLite إضافية عند تشغيل الخادم؛ لا يحذف الترحيل الجداول أو السجلات الموجودة. النسخة السابقة للترحيل محفوظة في `backups/before-template-versions.sqlite`. لا تكتبوا فوقها. قبل أخذ نسخة احتياطية يدوية، أوقفوا الخادم لإغلاق SQLite ونسخ ملفات WAL بأمان؛ احفظوا النسخة باسم جديد مؤرخ داخل مجلد نسخ احتياطي، ثم تحققوا من سلامتها باستخدام `PRAGMA integrity_check` على نسخة القراءة فقط. للاستعادة، أوقفوا الخادم أولًا، احتفظوا بنسخة منفصلة من قاعدة البيانات الحالية، ثم استعيدوا نسخة مختارة إلى `DATABASE_PATH` وتحققوا من سلامتها قبل إعادة التشغيل. قاعدة الإنتاج لم تُعدّل أثناء الاختبارات. لا تستخدموا `data/farhati.sqlite` للاختبار.

شغّلوا `npm run check` و`npm run build` و`npm test`. اختبارات التكامل تنشئ قاعدة SQLite ومجلد وسائط مؤقتين، ثم تحذفهما بعد انتهاء الاختبار؛ لا تستخدم بيانات العملاء الحقيقية.

## النشر على Render

أنشئ **Web Service** من مستودع المشروع، واختر بيئة **Node**. استخدم الإعدادات التالية:

- Build Command: `npm run build`
- Start Command: `npm start`
- Node.js: `22.9.0` أو أحدث (يضبط `engines` الحد الأدنى).
- Health Check Path: `/api/health`

أضف متغيرات البيئة في إعدادات Render، ولا تضع كلمات المرور في المستودع:

| المتغير | القيمة |
| --- | --- |
| `NODE_ENV` | `production` |
| `ADMIN_PASSWORD` | كلمة مرور قوية وفريدة |
| `DATABASE_PATH` | `/var/data/farhati.sqlite` |
| `MEDIA_ROOT` | `/var/data/media` |

أرفق **قرص Render دائمًا** بالخدمة عند نقطة الربط `/var/data`، وبسعة تناسب قاعدة البيانات والصور. يحتفظ القرص بملفات SQLite والوسائط عبر إعادة النشر وإعادة التشغيل. من دون القرص، نظام ملفات الخدمة مؤقت وقد تفقد البيانات والملفات عند نشر جديد أو نقل الخدمة. يدعم الخادم `PORT` الذي يعيّنه Render ويرتبط بـ`0.0.0.0` تلقائيًا.

أنشئ الخدمة والقرص أولًا، ثم اضبط المتغيرات، وبعدها انشر. تحقق من `/api/health` ومن تحميل الموقع والوسائط. لا ترفع `.env` أو أي ملف قاعدة بيانات أو صور خاصة إلى مستودع عام. ملفات `.env` وقواعد SQLite ومجلدات النسخ الاحتياطية والوسائط مستثناة في `.gitignore`؛ راجع أي ملفات سبق تتبعها قبل نشر المستودع.

تستخدم المنصة `node:sqlite` المدمجة مع Node.js 22.9 أو أحدث، ولا تحتاج حزمة SQLite خارجية. SQLite مناسبة لخدمة واحدة ذات قرص دائم؛ يجب تشغيل نسخة واحدة من التطبيق على ذلك القرص. إذا احتجت عدة نسخ متزامنة أو توسعًا أفقيًا أو توفرًا أعلى، فالأفضل نقل البيانات إلى PostgreSQL مُدار وتخزين الوسائط في خدمة ملفات/كائنات دائمة. إنشاء خدمة Render أو نقل بيانات الإنتاج يتطلب خطة ترحيل ونسخ احتياطية منفصلة.
